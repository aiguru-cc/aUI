# ADR-0005: 视图身份与增量渲染（T17）

- 状态：已接受
- 日期：2026-08-26

## 背景

ADR-0003 采用整树重建：每次状态变化销毁并重建全部 Tk 控件。缺点：
- 控件量大时性能下降；
- Tk 控件重建导致闪烁、输入框失焦、滚动位置丢失；
- 与 SwiftUI 的 diffing 模型不一致。

## 决策

引入**视图身份（identity）+ diff 渲染**：

1. **身份 = 结构性路径**。每个视图树节点在渲染时分配路径键
   （如 `root/0/1` 表示 root → child[0] → child[1]）。状态变化重建视图树后，
   相同路径的节点视为同一视图。这与 SwiftUI 一致：identity 是结构性的，
   而非对象身份（视图树每次重建，对象都会变）。

2. **Tk 后端维护 `path → widget` 映射**。渲染新树时：
   - 路径已存在且**类型兼容** → 复用控件，仅更新属性（text/fg/font/command/...）；
   - 路径已存在但**类型不兼容** → 销毁并重建；
   - 路径不在新树 → 销毁旧控件。

3. **兼容性规则**：`Text→Text`、`Button→Button`、`Toggle→Toggle`、
   `Slider→Slider`、`Picker→Picker`、`TextField→TextField`、`Stepper→Stepper`、
   `ProgressView→ProgressView` 可更新复用；类型不同或容器结构变化时重建。

4. **容器（VStack/HStack/ZStack/Form/List/Group）** 本身也占路径，
   子视图路径 = 父路径 + 子索引。容器类型变化时整棵子树重建。

## 后果

- 优点：状态变化只更新变化的控件；输入框保持焦点；无闪烁；与 SwiftUI 模型一致。
- 代价：结构性路径要求视图树**结构稳定**（不依赖条件分支动态改变子视图数量
  时仍可正确匹配——条件分支会改变路径，导致该子树重建，可接受）；
  实现复杂度高于整树重建。
- 演进：`ForEach` 显式身份（稳定 key）可作为后续增强，处理列表插入/删除的
  精确复用。

## 备选方案

- **对象 id 身份**：视图树每次重建对象都变，无法匹配，已拒绝。
- **用户显式 id 身份**：需用户标注每个视图，侵入性强，作为 ForEach 演进项。
