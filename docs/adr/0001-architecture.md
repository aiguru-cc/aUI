# ADR-0001: aUI 架构与设计原则

- 状态：已接受
- 日期：2026-08-26
- 决策者：aUI 维护者

## 背景

README 要求 aUI 是一个"基于 Python 的 UI 库，用于快速创建简单的用户界面，完全复刻 SwiftUI 的语法和功能"。核心诉求：

1. 声明式视图描述（与命令式 GUI 框架不同）
2. 状态驱动的自动刷新
3. 组件与修饰符（modifier）体系
4. 自定义组件支持
5. 零外部依赖、可快速上手

## 决策

### 1. 视图树 = 值语义的声明式描述

`View` 是轻量、不可变（约定）的 UI 描述对象，不直接持有原生控件。
渲染后端负责把视图树转成真实控件。这复刻了 SwiftUI 的 value-semantics 视图模型。

### 2. 布局引擎与渲染后端分离

布局（`size_that_fits` / `place` 协议）用纯 Python 实现，可在无显示环境
下单元测试。渲染后端可插拔：`AsciiBackend`（无头/测试）、`CursesBackend`（原生终端交互）。

### 3. 状态管理复刻 SwiftUI 三件套

- `State`：视图局部可变状态，变更触发失效/重绘
- `Binding`：双向引用
- `ObservableObject` + `@observable`：跨视图共享状态
- `Environment`：只读依赖注入

### 4. 修饰符为值对象

修饰符（padding/background/font/...）是值对象，按应用顺序组合，
由渲染后端解释执行。`frame` 因改变布局语义而结构性包装内容。

### 5. 渲染后端默认 curses

curses 是 Python 标准库（macOS/Linux 自带），零第三方依赖、无需显示
服务器，符合"快速创建简单 UI、便于后续开发"的定位。

## 后果

- 优点：可无 GUI 测试布局与状态；后端可替换；依赖为零。
- 代价：curses 后端为终端字符网格渲染，无原生控件外观；复杂布局
  （如自适应文本测量）为近似值。
- 后续演进：可增加更多后端（Web/Qt）、精确文本测量、主题支持。

## 备选方案

- **直接封装 Tkinter 命令式 API**：放弃声明式与状态驱动，不符合"复刻 SwiftUI"目标，已拒绝（Tk 后端随后整体移除）。
- **依赖第三方声明式库（如 textual）**：引入外部依赖，不符合零依赖定位，已拒绝。
